    Classifier Models ML1

    Classical machine learning consists of multiple models with differing architecture that can divide the state space up in differing ways, all based on their assumptions about how the data is distributed or the statistics of the decision boundary itself. For example, linear-equation-based models have an assumption that the target labels are linearly associated to one or more of the features; distance-based models assume that local, known data points inform the class of a new sample, and so on.

    In this section we will run through some of the main models, their assumptions, quirks, and limitations. There is a mixture of the intuition behind the models and also their maths: understanding the intuition behind the model is sufficient for beginning to use and critique the models.

    Logistic Regression

    Despite its name, logistic regression is a classifier and not a regression model. It is so named because it is an adaptation of a linear regression model, the simplest model where the assumption is that all $y$ values are the result of a linear equation:

    $$y = wx + b$$

    , where $w$ is the slope that multiplies $x$, and $b$ is the intercept, changing how high or low on $y$ the line starts when $x$ is 0.

    This can be seen plotted below. Try changing $w$ and $b$ to see how they affect the plot (pay attention to the scale of $y$).

    This can be extended to include multiple features by just adding the feature and its slope to the equation:

    $$y = w_1x_1 + w_2x_2 + b$$

    As it is no longer in 2-dimensions, the line is now called a plane. As before, we're limited to 3-dimensions for viewing the data, but the machine is not, allowing it to scale to create a plane in infinitely high dimensions. The beauty of linear regression and by extension logistic regression is that their understanding of the data is very transparent. If you were to train a linear-based model on a high-dimensional dataset, to find the most influential variable (feature importance) you would simply identify the slope values that are the largest, in absolute terms, that is, with no discrimination between large negative and large positive values. Those closest to 0 have little to no effect on the prediction. This trait makes these models a useful tool to help explain some of the more opaque models, such as deep neural networks — something we will cover in the Advanced AI module.

    WARNING

    The intercepts are only comparable if the features are all on the same scale, as small ranges will need multiplying more than larger ranges. Another reason for why it is important to scale your data.

    KEY TERMS

    line: A straight, one-dimensional path described by a linear equation with one feature, $y = wx + b$.

    plane: A flat, two-dimensional surface in 3D space, described by a linear equation with two features.

    hyperplane: The generalisation of a line or plane to any number of dimensions: a flat surface with one dimension fewer than the space it sits in, which divides that space in two.

    Adapting to a classifier

    With logistic regression you still want to model the output $y$ as a linear function, however, with the output changed from a continuous value (between minus infinity and positive infinity) to a probability of a label (between 0 and 1). To achieve this, it was proposed to transform the linear function by passing it to the standard logistic function, otherwise known as the sigmoid function.

    Below we have passed the output of the linear regression function to the sigmoid:

    When plotted, you can see the output has been squished between 0 and 1, forming an S-shaped line. With this shape we can now view the output as probability of either class 0 or class 1, with the more vertical section representing the more unsure decision boundary and the plateaus the more sure decisions. Typically, any value above 0.5 (the grey line) will be considered class 1 and anything below it class 0.

    For both linear (gradient descent) and logistic regression (maximum likelihood) the optimisation routine seeks to find the best values for $w$ and $b$ that best predict $y$.

    Limitations

    As with linear regression, the logistic regression model is limited by its assumption of a linear relationship between the features and the target variable. However, it is an extremely lightweight and simple to understand model, so it is always worth checking.

    K-NN

    k-Nearest Neighbours (kNN) is a non-parametric model or a lazy learner. This is because it doesn't learn from the training data, so there is no loss function or optimisation routine. Instead, the model infers a new sample's class directly from the training data. Here the kNN algorithm infers the class from the $k$ closest (nearest) examples, totalling the labels and choosing the majority as the label for the new sample. To always have a deciding vote, $k$ is normally an odd value.

    The closeness of two points is given by a distance, which is most frequently the Euclidean distance - the length of a straight line between two points, as calculated by the Pythagorean theorem (the diagonal of a right-angled triangle).

    Running the cell below, you can see the $k$ shortest Euclidean distances mapped to the plot; the predicted class is simply the one with the most dashed lines.

    Try moving the sample's coordinates closer to either group or to the corner, and changing the number of $k$.

    Benefits & Limitations

    Like logistic regression, kNN is a simple model to understand and implement. It maps well to many types of data, as true groups of data tend to cluster well, meaning being close to a cluster is highly indicative of a sample belonging to that cluster. Additionally, unlike logistic regression, it makes no assumption about the underlying data distribution, with the exception of the choice of the distance metric for differing data types. As the model requires all the training data for prediction, it does not scale well, with very large datasets potentially causing the computer to run out of memory. Counter to this, it will work well for very small datasets, as long as $k$ is small.

    Due to the reliance on counting neighbours, a kNN will struggle with heavily imbalanced datasets as there are simply fewer of one class to count in the vote. Where there is a low number of data points, the model can be sensitive to noise and outliers; however, these are typically ignored when the data is increased. kNNs can struggle with high-dimensional datasets, especially sparse ones, as the distance between points becomes more uniform. For example, if you had a heavily category-encoded dataset, a kNN may perform poorly.

    WARNING

    As kNN relies on distances, it is VERY sensitive to the scale of the features. They must always be standardised.

    Choosing K

    Picking the right value of $k$ is a balancing act of preventing under- and over-fitting. Choosing $k$ (a hyperparameter) is done during the fine-tuning phase, which we will cover in the next lesson. In essence, it is an empirical endeavour, where you change $k$ in a given range to observe how the performance changes on the validation dataset.

    TIP

    There are many distance metrics, ones to fit all types of relationships between data. If you are interested in further reading, this article describes many of them thoroughly.

    KEY TERMS

    parametric model: A model with a fixed number of parameters, which assumes a particular form for the data, such as the straight line of linear and logistic regression. Once trained, the parameters alone are used to predict.

    non-parametric model: A model that makes no fixed assumption about the form of the data, and whose complexity can grow with the amount of data, such as kNN, which uses the stored training data directly to predict.

    Decision Tree

    At the foundation of the tree ensembles (which will be covered next) is the decision tree. A tree will learn a set of rules on how to split the data, where each split should sort the data into a new group (node) that is more separated than before (more pure). When given new data, it simply follows the splitting thresholds, sending the data to the left or right branch, down the tree. When the data finally reaches a terminal leaf node, the decision is made about which class the sample belongs to.

    How the split is calculated

    In the diagram above we have all of the data at the beginning — $X$ — where the algorithm's job is to find the first best feature that splits the data. It does this by testing every feature with varying thresholds, that is values at which to separate the data into two halves. A split is said to be good when it best splits that feature in such a way that most (or all) of one class falls on one side and the same for the other side.

    This is demonstrated in the code below, where we have feature $x_1$. In this dataset there are equal amounts of class 0 and class 1, therefore as a whole it has an impurity score of 0.5 as it is 50/50 for each. By adding a threshold — which you can move with the slider — we have now created two halves. Notice, if you move the threshold so that only the red or blue class is in one half, the impurity value of it is 0, which is a perfect score. In doing so, this places more of a mix in the other half, increasing its score. A score can then be calculated by finding the average of the two halves scored, weighted by the number of values in each (otherwise a pure half of just 1 data point would count the same as one with a mix of 100s). To further normalise the score, we take the gain, which is the difference between the score when there is no split (in this case 0.5) and the weighted score. The largest gain across all features is then locked in as the chosen rule.

    NOTE

    Described above is the gini impurity criterion, the most commonly used score. For example, inside scikit-learn's implementation of a decision tree you can pick from gini, entropy, and log loss; with gini as the default.

    Optimisation Routine

    This process is replicated until the terminal node is just one class (pure) or when the limits set on the model are reached, such as maximum depth or minimum samples per split, which are model hyperparameters. Each split is greedy, which means it maximises for the current split with no reference (thought) to subsequent splits. This means a mediocre split that could enable a future, better split will never be chosen, a limitation of the system, but a trade-off for a computationally efficient system.

    Limitations

    As the rules are learned from the data, there are no assumptions made about how the data is modelled, meaning it can learn highly complex decision boundaries that take into consideration non-linear shapes to the data. However, despite this, decision trees are almost never used, as this benefit also means they have an extreme tendency to overfit to the data, learning the fingerprint (noise) of the training data as well as any true statistics.

    For this reason decision trees are mostly used as part of an ensemble, that is multiple trees, working in tandem or on subsets of the data.

    Tree Ensembles

    To overcome the weakness of decision trees it was found that creating a collection of trees, each that can only see a subset of the whole dataset, was much more accurate and crucially generalisable than a single tree on its own. This method, of collecting multiple versions of a model is called ensemble learning and is most frequently used with tree-based models, although it can be applied to any model.

    The learning paradigm is that if you have multiple weak learners, which are all at least better than random chance, then you can obtain a high accuracy by combining all their votes together and taking the majority rule. In fact, this is where the probability for random forests comes from, they are simply a totalling of the votes, normalised to a percentage. If 72 of 100 trees vote for class-1 then the probability is 0.72 or 72%. As each tree only sees a small set of data and is shallow in depth, the models can be trained extremely quickly in parallel and do not require lots of data, in stark contrast to deep learning methods.

    The two principal methods of ensemble learning are:

    KEY TERMS

    bagging: Short for bootstrap aggregating. Many models are trained independently, each on a random sample of the training data, and their predictions are combined by majority vote or averaging, as in a random forest.

    boosting: Models are trained one after another, with each new model focusing on correcting the errors of the previous ones, and their predictions are combined as a weighted vote, as in AdaBoost and gradient boosting.

    Random Forest

    The most common bagging ensemble model is the random forest (RF), which we have used extensively throughout this lesson. RFs work by generating $T$ decision trees, where each tree sees a random sample of the training dataset with all the features. The sampling is done with replacement, so a sample can appear more than once per tree and in multiple trees, increasing the $N$ per tree for small datasets. Each tree is then trained as explained above, with the exception that instead of picking the best feature per split from all features, it can only select from a random subset of features. This is to prevent the trees all replicating each other, as in cases where one feature is strong they will all replicate each other.

    Once trained, a new sample is given to each tree and it flows down the tree's decision gates until each gives its own prediction, which is used to pick the most likely class by the majority. See the visualisation below:

    Limitations

    Due to having multiple weak learners, RFs tend to be fairly robust to overfitting as each tree is only exposed to some or little of the noise and outliers. For this reason they tend to be the classical machine learning model that performs best straight away. The model's limitations are often the general limitations of ML: the data is overly noisy or not representative of the problem.

    When working with RFs the most important hyperparameters for tuning tend to be the number of trees and the number of features to consider at each split — max features in scikit-learn.

    How feature importances are calculated

    In the final part of the second section we obtained the feature importances to select the top 3 features. Now that we know a bit more about RFs, we can explain how they are calculated. In the decision tree subsection we saw that each split aims to reduce the impurity. A feature's importance is the total of the impurity reduction it creates, over all splits it is involved in, weighted by how many samples there are at each split. Therefore, features that bring about the greatest increase in purity in the greatest number of samples will have the highest score. These values are then normalised to sum to 1.

    SVM

    Support vector machines (SVMs) work by separating the feature space using a line/plane/hyperplane (see earlier) such that the separator maximises the distance between itself and the nearest points of each class. As before, we have a linear equation, except in this circumstance the output ($y$) is not the result of the linear equation; rather, it is which side of the line the data point falls on, or:

    $$y = \text{sign}(wx + b),$$

    where sign is a mathematical operator that returns +1 if the input is positive or -1 if it is negative, giving us two numbers that represent our classes, as they fall on either side of the hyperplane.

    In the plot below, an SVM has been trained on the data, producing the hyperplane (black), its margins (grey), and support vectors (encircled). The hyperplane is where $wx + b = 0$, i.e. no decision, and lies midway between the two margins. The support vectors are the points that lie on the edge of the margins and are what define where the margins sit. Only the support vectors influence the hyperplane (hence the name), meaning points that sit well within their own class's cluster have no effect on the prediction function.

    The aim of the optimisation algorithm is to maximise the size of the margin, so that the hyperplane is equidistant from the closest examples of each class. Thereby, the model focuses on learning how to best separate the most difficult points.

    Dealing with Noise

    In the example above, the parameters for the hyperplane are simple: it lies midway between the support vectors of each class. However, in practice (and as seen below) classes often overlap and are not perfectly separable. This means that the model needs to allow for some misclassification to be of any practical use. This is achieved through the hinge loss function, which returns a score of 0 when a data point is on the correct side of the decision boundary and outside the margin; otherwise, it returns a value that is proportional to how far the point sits past its margin. This means that points just inside the margin receive only a small penalty, whilst egregious predictions are penalised heavily. Points that fall within the margins are also support vectors.

    To control how many misclassifications are allowed (and thereby the width of the margin), the hinge loss is weighted by the hyperparameter C and combined with the margin term to form the cost function. C is a constant that multiplies the value from the hinge loss, such that a small C permits many violations, as it reduces the penalty for each one, giving a wide margin and many support vectors; whereas a large C penalises them heavily, giving a narrow margin defined by only a few points.

    $$\text{Cost} = \underbrace{\frac{1}{2}\lVert w \rVert^2}_{\text{margin term}} + \; C \times \underbrace{\sum \text{hinge loss}}_{\text{misclassification}}$$

    As with $k$ in kNNs, finding the right C is empirical. Whilst it may seem like restricting misclassifications will give better accuracy, it means the model is likely to overfit to the training data.
