    Introduction

    In step 2 of the machine learning (ML) process the model algorithmically builds the statistical approximation during training.

    This consists of three building blocks:

    1. The Loss Function: How the model measures how wrong its predictions are for each sample in the training dataset.

    2. The Cost Function: The augmented, summed values from the loss function from the whole training dataset.

    3. Optimisation Routine: The algorithm that searches for the best solution given the value from the cost function.

    Given these three building blocks, an ML model will iterate (loop through) all the samples in the training dataset, updating its parameters after each time the whole dataset has been processed (an epoch). Think of the parameters as a set of dials and knobs that the optimisation routine can change in response to the feedback it gets from the cost function. The loss function, cost function and optimisation algorithm can be unique per model, although many share the same, such as gradient descent. These concepts will be explored more in the lecture for this lesson, as well as ML4.

    In practice, you will rarely need to build these yourself when using classical ML tools. In scikit-learn, the Python package we will be using throughout this module, each model comes with its loss function, cost function and optimisation routine already built in and set to sensible defaults. Where there are choices to be made, it is around modifying what the model assumes about the data, such as the number of splits in a random forest. These are the hyperparameters, which, as described, are chosen before training, unlike parameters, which are updated during training. These will be explored in the next lesson ML2. A conceptual understanding of the three building blocks is therefore enough for now: it tells you what those settings are doing, and why a model might struggle to learn.

    KEY TERMS

    parameters: Values inside the model that are learned from the data during training, such as a weight in a regression or a split threshold in a decision tree.

    hyperparameters: Settings chosen by you before training that control how the model learns, such as the number of trees in a random forest.

    Scikit-Learn

    Scikit-learn is an all-encompassing Python package for machine learning, containing the majority of models and a myriad of tools to prepare, transform, and clean data. It is open-source and one of the most popular packages for ML across all programming languages. What scikit-learn does well is to wrap computationally difficult aspects of ML into single functions, allowing the user to chain together several functions in a pipeline with only a few lines of code. This allows you to focus on your approach, rather than the code itself. A good example of this is the three building blocks, which are all executed via efficient code using a single method: .fit(), which we will see later. That's it, one line of code to fully train a model.

    Additionally, scikit-learn has been designed to integrate seamlessly with numpy and pandas, so you can easily flow from your data exploration and cleaning workflows into machine learning.

    What we cover in ML1-3 will only scratch the surface of the offering of scikit-learn, with many specialist tools for unique problems and data. Therefore, it is worth exploring their documentation to see if they have already tackled a problem similar to the one you're working on.

    Splitting the Data

    The first step in machine learning is to split the data into at least two groups: the training and test datasets. This must be done at the very beginning, before many data cleaning techniques, to avoid data leakage, which will be explored next. In essence, you should not have any information from the test data come into the training data, as this can give your model information to learn about the test data.

    Think of your test data as questions that test whether the model has learned the general nature of the data, rather than learned it by rote.

    The training data is typically between 60-80% of the dataset. You want to maximise as much in this group as possible, as it increases the accuracy of the model's decision boundary. However, it comes at the cost of samples to test the model, where you would want at least 30 to 100. It therefore becomes a push and pull, with easier decisions when you have a high number of samples in your data.

    There is a third group, the validation dataset, which can be used to optimise the hyperparameters. This is not always needed, as this can be performed by sub-sampling the training dataset, as will be seen in ML2.

    Split Purpose Proportion of Total Data Usage Frequency
    Training set Used to train the model. ~60-80% Always
    Validation set Used to fine-tune the model & track training. ~10-20% Often, but not always
    Testing set Used to evaluate the model’s performance, providing an indication of how well it has learned. ~10-20% Always

    Data Leakage

    Splitting the data early and preventing the model from ever seeing the test data is the most obvious method for preventing data leakage. This is not what trips most people up; instead, data leakage often comes about when the statistics of the test dataset sneak into the training data.

    This can come in many forms, such as:

    • multiple samples from the same subject: If samples contain repeated measurements from the same subject, the model can learn the specifics of that subject and not the general shape. In this situation, all subjects must be in either the training or the test set, not both.

    • replacing missing data: Many datasets come with missing values; these need to be replaced with a number, normally the mean or median. If this value is calculated from the whole dataset, then the test samples' statistics are leaked. How to do this will be covered in the next sub-section.

    • scaling on all the data: Features come in all ranges and shapes. These are often transformed to be more uniform to help the model train. As with missing data, if the transformation comes from the data statistics, the test data is leaked. This will be covered in more detail later.

    • data that contains time: If your dataset includes time as a feature you must only use data from the future in the test, as the assumption is often that the past predicts the present.

    • tuning the hyperparameters with the test: Sometimes users will optimise the model's choices (hyperparameters) with the test data, as they believe it doesn't affect the training. This will skew the model choice to fit the test data.

    You can also have proxies for the target feature. This could be sample unique IDs that aren't removed or data that is recorded after the event/label occurs, such as post-diagnosis medications. A more subtle version of this would be descriptive statistics that inform something about the data you are trying to hide from a model, such as the length of the time series / sequence in spectral analysis. You should therefore always know the exact information you are providing.

    Checking for data leakage

    We are not perfect, so there will be times when you have accidentally leaked into the training data. To catch these mistakes it is imperative you properly interrogate your model's predictions, to find out why it performs so well. This can be done by using feature importance (see the end of this section) and finding a suspicious predictor that you think would not normally be this important or dominant, or by finding newer test data, one that you validate the model on in a fresh exploration session. The former will help you with data leakage via proxies — target information — and the latter with leakage of the testing statistics.

    Data Cleaning

    Most data does not arrive without faults: categorical data needs to be standardised, outliers/errors removed, etc. Cleaning the data before training is therefore one of the most laborious tasks of machine learning.

    The most common issue that needs to be fixed is missing values, which in numpy & pandas present as NaN (not a number) values. These often occur from missed measurements by a sensor, or differences in collection routines.

    To check if any column has missing values, use the isnull() method combined with any() to find out. The first part returns a boolean array per feature where True is present for any row with a NaN in that feature, the second part condenses it down to a single value by returning True if any item in that array is a True.

    We are working with only the training dataset first, to inform what our replacement values should be.

    The result shows us that the symmetry feature has some NaN values. As isnull() produces a series/matrix of boolean values, this can be used to filter the dataframe to just show the rows with the missing values. Run the cell below to see:

    Machine learning models cannot intrinsically handle missing values, as we saw in the previous section that they work on the whole high-dimensional space. To miss a value is to not have the final number in a set of coordinates. To this end, a decision must be made about what to do with the affected samples.

    The simplest method is to drop any sample/row with missing values, as any replacement would be a guess and one that could bias the model. This is effective when the number of samples with missing values is a small fraction of the dataset. For this, dropna() can be used, subsetting to a specific feature if needed.

    More often, you don't have data to throw away, in which case you must decide on a replacement that will minimise biasing the model. In many cases this will be replacing the missing value with the average, with the understanding being that this value is the least discriminatory; in this case the mean or median will do. For training, where a feature is differently distributed for the target class, the average for each class can also be used, to help reinforce the differences. However, it must be noted that you will not have this option for the test or new data, as the class won't be known, so this can only be used on the training data (see later in this section).

    To replace values use .fillna() instead.

    Scaling

    The last, but important, step before training is to re-scale any quantitative data. As briefly discussed in the state space section, the models are indifferent to the units your data comes in. They can be kilometres, counts, seconds, etc.; all the model wants to use is the separation or grouping of the samples in the state space.

    Having features of vastly different scales can negatively affect the model's ability to separate the data, as is visualised below. Moving the slider to the right increases the scale of the feature 1, distorting the data:

    ▶ Show code

    As is visually clear, having one feature on a vastly different scale distorts the geometry of the space, ensuring that this feature dominates the others. This matters a lot for any model that is built around distances. Larger scales can also affect the optimisation of the model during training, but we will not go into detail on the mechanics of this.

    NOTE

    Not all models need the data scaled. In particular, models built with decision trees (random forests) do not require it, as they are invariant to distance. However, it often doesn't hurt to apply it, so it can still be good practice. Which models do and don't need it will be discussed further in the model types section.

    Applying scaling

    Back to the breast cancer dataset, cherry-picking a few features demonstrates the differences in scale:

    These distributions are roughly bell-shaped, with some skew and no extreme outliers, so the mean and standard deviation summarise each feature well. We can therefore standardise or rescale each feature to a mean of 0 (by minusing the mean) and a standard deviation of 1 (by dividing by the std). Each value would then become a reflection of its change away from the feature's mean, so every feature is now expressed on the same scale regardless of its original units. Note in the plot further down, post scaling, that the shape is the same.

    The equation for this is:

    $$ \frac{x_i - mean(x)}{stdev(x)} $$

    This type of transformation is standard scaling, which can be applied using scikit-learn's StandardScaler:

    The standard scaler is the most commonly used, but it is not the only one. Notable other scalers are:

    • robust scaler: Like the standard scaler, except it is robust to outliers, preventing the mean being pulled towards them. Use this when you have outliers present that are not anomalies.

    • min-max scaler: Scales the data to have the minimum value be 0 and maximum value of 1 (this can be changed to -1 and 1). Use this when you don't think your data is normally distributed and you want to preserve its structure. This would be anything with a meaningful range, such as counts out of 100, percentiles or speed, or anything where you want to maintain the relative distance.

    There is also the Normalizer, which works sample-wise (row) rather than feature-wise (column). By default, it rescales each row to a nominal value such as 1, giving the proportion of each feature to that sample. It discards each feature's true value and replaces it with a set of numbers that describes its direction in the feature space. This is most useful when you have many features on a common scale, such as expression count or activity, where you are more interested in the proportion of each feature compared to the others in the sample, rather than each feature's amount, as in these cases samples can have varying total magnitudes purely from the randomness of measurement. Here, larger values will naturally dominate the end product; however, this is by design, as they represent the highest proportion.

    All of these are demonstrated further in the notebook scaler_demo.ipynb inside your additional resources folder.

    Predict

    Use .predict() when you are just interested in the model output. As an input you provide the scaled data, receiving an output array that matches the number of samples in the input. This is usually done once the model has been evaluated and trusted, to generate labels for a new set of data.

    Accuracy

    The simplest statistic for evaluating a classification model is the accuracy: how many predicted labels match the labels in the ground truth array $y$. The method .score() will match the predictions from the given data with the ground truth, providing a number between 0 and 1, where 1 is all predictions were correct and 0 all are wrong.

    Probabilities

    In the first section we discussed the model's confidence in its predictions. Most models do not just provide a single label, rather they give their belief it is one or another in the form of probabilities (together sum to 1). You retrieve much more information when looking at the probabilities, as all that .predict() is doing is returning the label of the category with the highest probability, which in a binary problem means $\geq 0.5$.

    The resulting array will have a shape $N \times L$, where $N$ is the number of samples and $L$ is the number of target labels. The first item in each row will be label 0 (benign) and the second item label 1 (malignant).

    Working with the probabilities allows you to have more control over the confidence in the prediction. A classic example is in disease prediction, where you want to be sure that the prediction is true before proceeding.

    Feature Importance

    Unique to tree-based classifiers are feature importances, a metric of how much a feature contributed to the prediction — the mechanics will be explained in the final section. Each feature is given a proportional value (all sum to 1), meaning the largest values indicate a greater share in the contribution to the prediction.

    The importances are calculated from the training data, so you must be sure the model is a true representation of the data through testing before moving forward with the investigations.

    NOTE

    There are alternative methods for other models that will be covered in ML2 and more in-depth in the Advanced AI module.

    Summary & Quiz

    In this section, we introduced the three building blocks of training (the loss function, the cost function and the optimisation routine) and saw how scikit-learn wraps them all into a single .fit() call. We worked through the practical steps that come before it: exploring the data, splitting it early to avoid data leakage, handling missing values, encoding the target and scaling the features with a scaler fitted only on the training data. We then trained a random forest, evaluated it with .predict(), .score() and .predict_proba(), and used probability thresholds to control how confident a prediction needs to be. Finally, we used feature importances to pick a small set of informative features, and retrained the model to visualise its decision boundary in 3D.
