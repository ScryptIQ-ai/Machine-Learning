    Introduction

    All machine learning (ML) models are designed to learn from the unique patterns of a dataset, in the hope that the representation they learn approximates the true statistical distribution/model of the population data.

    With classical ML, which we will be working with in ML1-3, the approximate function is typically built using the original data features, or features engineered by hand from the original measurements. This is called shallow learning, which stands in opposition to deep learning, which we will explore with neural networks in ML4. With deep learning, the data goes through several transformation stages — learned in training — that reshape the data into a new form, one that the model can solve more easily. This is very useful with large, messy datasets where you are not sure which information is important. However, remember that it is not a silver bullet for bad data, as bad data mixed in can still affect the quality of the prediction.

    Deep learning is not automatically better than shallow or classical ML tools; for starters, it requires a lot more data and compute to train. It is always worth attempting your problem with the classical tools first: firstly, to gain a quick insight into whether it looks feasible, and secondly, because they are better tools for understanding which features contributed to the prediction, giving you insight into the system rather than being stuck with a black box.

    KEY TERMS

    function: A mathematical rule that transforms an input into an output. In ML, the trained model is the function, mapping the measurements you give it to a prediction.

    feature: A single measured variable in a dataset, such as a gene's expression level, a cell's area, or the minutes a fly is asleep. Each feature forms one axis (dimension) of the state space.

    shallow learning: Classical ML, where the model learns directly from the original features, or from features engineered by hand, rather than learning its own transformations of the data.

    deep learning: ML using neural networks with many layers, each learning a transformation of the data, so that the model builds its own representation of the features during training.

    compute: The processing power, and time, needed to train or run a model, typically provided by CPUs or GPUs.

    Machine Learning Workflow

    The machine learning process can be broken down into three steps:

    1. Gather the dataset — one that properly represents the nuances of the population (often the hardest part).

    2. Algorithmically build a statistical model or function based on that dataset, iteratively improving the model's parameters to match the data.

    3. Apply the trained model to new data from the population; if it is correct, it is assumed the model has solved the practical problem. This is the key test of any model: can it work with new data or, in other words, does it "generalise" well?

    In mathematics, the model or function ($f$) is something that transforms the data you gathered ($x$) into the output you want ($y$), be it a classification, a regression or a next-in-sequence prediction. Therefore, the algorithm's aim is to iteratively build a function that best produces $y$ when given $x$, or:

    $$y = f(x)$$

    KEY TERMS

    $x$: The input to the model: the measured features of each sample.

    $y$: The output the model is trying to predict: a class label, a continuous value or the next item in a sequence.

    algorithm: A step-by-step procedure for solving a problem. In ML, the training algorithm is the procedure that iteratively adjusts a model's parameters to fit the data.

    parameter: A value inside the model that is learned from the data during training, such as a weight in a regression or a split threshold in a decision tree. Not to be confused with hyperparameters, which are chosen by you before training.

    For Differing Problems

    Each model comes with its own assumptions about how the data is organised: linear and logistic regression models, for example, assume a linear relationship in the data, while nearest-neighbour models assume that the distance to neighbouring points is the only factor that matters. Even neural networks — which in theory can learn any complex function — have a bias towards simple models of the data. What helps is knowing the use cases and limitations of each model, which then informs how you interpret its output.

    "All models are wrong, but some are useful."

    George Box

    Many of the models can be turned towards differing tasks, the most common being classification, where the model must distinguish between two or more groups within the same measurement space (state space). This may be most familiar to us all through image classification, which has seen large improvements with deep learning. Alongside classification, regression is the other classical task. Instead of predicting a group, the model tries to predict a continuous value, such as expression level, rainfall or growth rate. Regression modelling can be very useful for in silico perturbation models, changing the system state to estimate its effects. This module will largely use classification as the example; however, all the skills are easily transferable.

    Lastly, there is the generative task, which has grown substantially in the last decade. Here the model is trained to predict the next item in a sequence, as with large language models (ChatGPT, Claude, Gemini, etc.), or to generate an image or dataset from an input. These will not be covered in this module, although they are touched upon in the advanced AI module.

    KEY TERMS

    classification: Predicting which of a set of discrete groups (classes) a sample belongs to, such as healthy vs diseased tissue.

    regression: Predicting a continuous numerical value, such as an expression level or a growth rate.

    generative: Producing new data — the next item in a sequence, an image or a synthetic dataset — that resembles the data the model was trained on.

    The State Space

    To help visualise the intuition behind machine learning, we can explore the three steps of the machine learning process — outlined above — through a series of 3-dimensional (3D) plots.

    For many, the purpose of machine learning is to make intractable data understandable, be it proving there is a difference between two groups, finding the important features in a multi-feature (high-dimensional) dataset, or building an in silico tool for testing perturbations of a complex system. To that end, understanding conceptually how the models work, and how they can be right or wrong, is more important than knowing the exact maths behind them, as those without a background in mathematical notation can find the equations as intractable as their data.

    Machine learning models are learners rather than solved equations — even though they are underpinned by mathematics, particularly linear algebra — so they can be approached heuristically, using ideas and understanding from low-dimensional space to inform our decisions when working with higher-dimensional data.

    A Hypothetical Space

    When measuring something, we are gathering data from a range of values, ones that hopefully represent the object or group that we are interested in. This measurement space can range from $-\infty$ to $\infty$, although it is usually bounded by the physical limits of the system. If something was measured repeatedly and all values in the range were present uniformly, i.e. one of every value, that would likely be random noise, meaningless to us. Normally, however, the data we gather contains only a subset of values from the space: values that describe that particular thing. These values can be large or minutely small; the numbers themselves do not matter at all. Instead, what matters is where the values sit in that range in relation to each other: their difference.

    It is this mindset that is useful for machine learning, as it is what the ML tools are interested in: the differences between values within a feature, and in combination with other features. In a classification task, the model uses those differences to separate the state space into areas belonging to one group or another. In the next section, we will look at scaling the data as one of the best methods for improving the model, transforming it into values that represent change rather than raw measurements, as discussed briefly in the data processing module.

    The Decision Boundary

    Now that we have our samples (at differing $N$), a model can be built from the data. For this example we will use a Random Forest (RF) Classifier, which will be explained properly in the final section. RFs are very good at finding non-linear boundaries between classes, as they separate the data using splitting rules built from the sample data, e.g. if feature 1 is greater than 0 and feature 2 is less than 2.5, it is class-2.

    The divide in the state space is called the decision boundary, and it can be thought of as the high-dimensional equivalent of a line, marking where the model becomes more sure of one class than the other. In a two-class problem, this divides the space in two.

If new data were given to the model, every data point inside the boundary would be predicted as class-2, and every point outside it as class-1. However, using our eyes we can see that class-1 is confined to a much smaller shape than the whole state space. Yet if we gave the model some data points from a corner of the state space — well away from the true distribution — it would still predict them as class-1. This is because, in a classification task, the model's job is to model the statistics of the boundary between the two classes, not the classes themselves.

    Testing the Model

    The decision boundary above was generated from the sample; the data we give a model to learn from is called the training data. An ML model is very good at fitting its decision boundary to the training data, but this can come at the cost of being correct on new, unseen data, as it can learn the noise and data fingerprint of a specific collection of data rather than the true population statistics. In fact, much of the fine-tuning is there to prevent it from learning this data fingerprint or, in ML lingo, to stop it overfitting.

    To this end, a model's worth can only be understood if it performs equally well on new data, preferably data from the same population but sampled at another time — hopefully losing the previous experimental fingerprint. If a model does well, then it can be said to generalise well to the problem.

    KEY TERMS

    training dataset: The data the model learns from, used to fit the model's parameters.

    testing dataset: Data held back from training and used only to evaluate how well the model performs on data it has never seen.

    overfit: When a model learns the noise and quirks of its training data rather than the underlying pattern, performing well on the training data but poorly on new data.

    generalisable: Describes a model that performs well on new, unseen data from the same population, not just on the data it was trained on.

    The test data should never be seen by the model during training, as it is your main tool for validation; if the model ever has access to it, or a proxy for it, this is called data leakage. Ideally, the test data should be a fresh sample collected using the same techniques and equipment, to ensure repeatability. Beyond that, the hope is that the data and the chosen measurements truly reflect the population statistics, to the extent that variations in equipment and timing windows do not distort the data too much.

    In practice, most datasets come as a single collection and are split into training and testing groups after sampling. Many people simply shuffle the data randomly and split it; however, if you are able to hold out a single experimental group, it can strengthen the test. For example, financial trading models are often trained on all previous data except the last month, which is kept back for testing. This is especially important when the data has time as a feature.

    In this situation, no amount of additional data or fine-tuning can improve the model, as the class points occupy the same space. This leaves you with transforming the data, in the hope that the transformed points are more cleanly separated. This is one of the benefits of deep learning, as its many layers transform the data to be more separable by the final layer, making otherwise intractable data solvable by design.

    With Probabilities

    The issues stated above can be mitigated, or better understood, by approaching the output of a model as probabilities rather than a binary classification (it is or it isn't). Most models do not just give a class; instead, they provide a probability, which indicates their confidence that it is one class or the other. In a binary (two-class) problem, the class with a probability over 50% (0.5) is the winner, with the two values summing to 100% (1). The closer the two values are to 0.5, the more unsure the model is, with the prediction becoming a coin flip at 0.5.

    KEY TERMS

    confidence: Most machine learning models express their output as a degree of belief, in the Bayesian sense. The value given is not the chance that something will happen, but rather the belief, or confidence, the model has in its prediction.

    True Shape

    Now that we have explored the machine learning process in full, we can reveal the true distributions the classes were drawn from.

    Class-1 is a torus, a 3D surface shaped much like a doughnut. The samples lie on the surface of the torus, meaning they exist exclusively on a 2-dimensional surface that has been embedded in 3D space. This will be explored further below.

    Class-2 is a much thinner torus that sits inside class-1.

    Move the plot around below and look at the shapes from different angles. Separating the two may look easy to the human eye, but it is a complex problem that can only be solved in 3D space: the classes heavily overlap on each individual feature, and even when viewed face-on from any side, the two still overlap. Only by combining all the dimensions can the model make an accurate prediction. This is one of the arguments for high-dimensional datasets: provided the extra features carry useful information, they give the problem more space in which to be solved.

    Moving to Higher Dimensions

    So far we have worked in three dimensions, as that is as far as our puny minds can visually comprehend. Most datasets that researchers want to apply to machine learning rarely stop there, as they would likely be solvable with traditional statistics.

    RNAseq, microscopy images, and neural recordings can all produce data that has dimensions of 1000+. These cannot be plotted, but the ideas from the torus carry over directly.

    The Manifold

    Look back at the class-1 sample and the true distribution. As stated, all the points lie on the surface of the torus, a 2D surface in 3D space. You need three numbers (feature 1, 2 and 3) to record where a point is, but only two numbers to describe where it sits on the surface: how far around the ring it is, and how far around the tube. The number of features we measure is called the ambient dimension, whereas the number of values needed to describe the data itself is the intrinsic dimension. For the torus, the ambient dimension is 3 and the intrinsic dimension is 2.

    The surface the data lies on is called a manifold: a shape that has a lower dimension than the ambient dimension when you zoom in close enough. Much like the Earth looks flat from where we stand, despite being a sphere.

    The Manifold Hypothesis

    The manifold hypothesis proposes that the same is true of most real, high-dimensional data: although it is measured with many features, it lies on or near a manifold of far fewer dimensions.

    Take gene expression as an example. A cell's expression profile has 20,000 values, but those values are not free to vary independently. Genes are co-regulated by shared transcription factors, pathways switch on and off together, and a cell's state is largely set by a handful of underlying processes: its type, where it is in the cell cycle, how stressed it is. Of all the possible combinations of 20,000 expression levels, only a vanishingly small fraction are biologically viable cells. The data occupies a thin, curved surface in an enormous space, just as the torus occupies a thin surface in our cube.

    The Manifold Takeaway

    Hopefully this demystifies the term manifold that is so often thrown around by ML scientists; it is just a shape in high dimensional space where most of the data lies. The ML model's job is not to split the entire state space, which, given its near-infinite size, is very large. Instead, the model can tackle the much more tractable problem of finding the decision boundary that separates the two manifolds in the space.

    Understanding it in this context further demonstrates why the model performs so poorly when predicting a corner of the state space. The model confidently called it class-1, yet no data lives anywhere near there, as the model's predictions are only meaningful close to the manifold it was trained on.

    KEY TERMS

    ambient dimension: The number of features used to measure the data, i.e. the number of axes in the state space.

    intrinsic dimension: The number of values needed to describe where a point sits within the data itself; for the torus surface this is 2, despite it living in 3D.

    manifold: A shape that looks flat when you zoom in close enough, which the data lies on or near within the larger state space.

    manifold hypothesis: The proposal that real high-dimensional data lies on or near a manifold of far fewer dimensions than the number of features measured.

    Summary & Quiz

    In this section, we introduced the state space as the set of all possible feature combinations, and showed how a classifier divides it into regions with a decision boundary. Using a random forest, we saw the boundary refine as the number of samples grew, then tested it on unseen data to check how well the model generalises. We then viewed the model's output as probabilities, a measure of confidence that is lowest near the boundary. Finally, we revealed the true shapes behind the classes, and used them to introduce manifolds and the manifold hypothesis: real, high-dimensional data tends to sit on a much lower-dimensional surface, and a model is only reliable close to the data it was trained on.
